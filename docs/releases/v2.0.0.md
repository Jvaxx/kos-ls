# kos-ls 2.0.0

First **stable release** of the independent, server-only
[kos-ls fork](https://github.com/Jvaxx/kos-ls), based on John Chabot's
[kos-language-server](https://github.com/jonnyboyC/kos-language-server)
at `aff3a4743f5492a878cbfb5d2938e2e90f83cb45`.
Targets **kOS 1.6.0.1 / KSP 1.12**. Requires **Node.js 22.13 or later**;
Node.js 22 and 24 are tested. This is a GitHub release, not an npm
registry publication.

## Highlights

- Reliable workspace startup and dependency propagation, volume mappings,
  runtime library preloads, exclusions and root `ksconfig.json` reloading.
- Generated kOS 1.6.0.1 builtin metadata and documentation for richer
  completion, Markdown hover and signature help.
- Typed user doc comments, inferred-type inlay hints, semantic highlighting,
  quick fixes and disk-size code lenses.
- Document/range formatting and the `kos-ls format`, `kos-ls check` and
  `kos-ls size` commands for editor-independent workflows and CI.
- Parser, type-checker, system-lock, builtin-reference and completion fixes,
  including completion inside nested or unfinished return expressions.
- A source-inclusive package with editable kOS and runtime dependency
  snapshots, provenance/checksum manifests, an offline source verifier and
  retained upstream license notices. One skipped upstream regression-test
  URL was neutralized rather than redistributing its image-download token;
  runtime dependency source is unchanged.

## Validation

The full suite has **1,000 passing tests** on both Node.js 22 and 24.
Release preparation also verifies source/fixture checksums, clean-source
and packaged builds, database regeneration, CLI/LSP smoke tests and
reviewed secret scans. See [the release procedure](https://github.com/Jvaxx/kos-ls/blob/v2.0.0/docs/RELEASING.md).

## Install

```sh
curl -fLO https://github.com/Jvaxx/kos-ls/releases/download/v2.0.0/kos-ls-2.0.0.tgz
curl -fLO https://github.com/Jvaxx/kos-ls/releases/download/v2.0.0/SHA256SUMS
sha256sum --check --ignore-missing SHA256SUMS
npm install --global ./kos-ls-2.0.0.tgz
kos-ls --version
```

Configure the LSP client to launch `kos-ls --stdio`. The `kls` alias is
included, but `kos-ls` avoids collisions with old upstream installations.
No VS Code extension, snippets, TextMate grammar, game launcher or telnet
client is bundled.

For source builds, clone or extract the source archive, then run `npm ci`,
`npm run verify:sources`, `npm test` and `npm run bundle`. `npm run build`
alone does not update the `bin/kos-ls` launcher, which uses `dist/`.

## Assets

- `kos-ls-2.0.0.tgz`: installable, platform-independent Node.js package,
  including the ready-to-run bundles **and matching project source**,
  shrinkwrap lockfile, editable upstream inputs and license notices.
- `kos-ls-2.0.0-source.tar.gz`: explicit source archive of the tagged tree,
  with its canonical lockfile and pinned third-party input snapshots.
- `kos-ls-2.0.0.spdx.json`: SPDX inventory of the runtime dependency tree.
- `SHA256SUMS`: SHA-256 checksums for the three assets above.

Checksums detect corruption; they are not a separate cryptographic
signature. Download the assets from the GitHub release over HTTPS.

## Compatibility and limitations

Use the `kos-ls` client-settings section (`kos-vscode` is a fallback),
root `ksconfig.json` for analysis, and `.kos-format` / `format` sections
for formatting. Formatter configuration is file-based, not editor tab
settings. See [migration](https://github.com/Jvaxx/kos-ls/blob/v2.0.0/docs/FORK.md).

Static analysis cannot discover all runtime-computed run paths or dynamic
suffixes; model known runtime libraries with `preload` or `// #include`.
Disk sizes estimate stripped source, not compiled `.ksm` files. The
formatter is LLVM-inspired, not clang-format itself, and does not format
syntax-invalid files or implement tabs. See the
[limitations](https://github.com/Jvaxx/kos-ls/blob/v2.0.0/docs/ROADMAP.md).
